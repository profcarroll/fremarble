BUG-001: marble sinks into a wall on diagonal movement, then is pinned forever.

Evidence (telemetry/run2.csv, tilt down-right ax=-300 ay=-600 into the pocket floor at y=400,
marble radius 18, so the lowest legal center is y=382):
  t=8.9  x=606.0 y=385.6  vx=-1.02 vy=0.23   <- already 3.6 px inside the floor
  t=9.9  x=622.1 y=403.0  vx=-1.16 vy=-0.83  <- 21 px inside the floor
  t=10.5 x=623.0 y=403.2  ... identical for the next 15 s, velocities alternate sign every frame
Cause: the wall test moves both axes at once, then on collision cancels only ONE axis
(abs(vx) > abs(vy) picks x). Moving diagonally into a floor therefore keeps the y move and
the marble enters the wall; once inside, every frame collides and it never escapes.

Fix required in game.py, nothing else changes:
1. Resolve axes separately: try the x move alone (rect at nx,py); if it collides with any
   wall or screen edge, cancel it (nx=px, vx=-vx*0.6). Then try the y move alone (rect at
   nx,ny); same treatment. A marble can then slide along a wall it is pressed against.
2. Safety: if after resolution the marble rect still overlaps a wall (it should not), push it
   out along the axis of least penetration so it can never be pinned.
3. Keep telemetry, events, arguments, output line and exit codes exactly as they are.
Output the complete corrected game.py as a fenced block preceded by '=== FILE: game.py'. Nothing else.
